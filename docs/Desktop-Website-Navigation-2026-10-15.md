# Desktop website navigation — October 15, 2026 (AF-UI-040)

Larry reports that clicking Downloads in the installed 4.3.1 desktop app opens the reader's “That reading link is not valid” error. The desktop entry point handles Library and reader/Sources routes; `/downloads` is a website-only page. Its relative link was treated as local, bypassing the system-browser opener and falling through to Scripture route parsing.

The prepared fix resolves local Downloads, Privacy, Terms and Support links to the corresponding `https://ad-fontes.app` URL before the existing capture-phase external-link handler classifies them. The opener preserves the current study in the app. Queries and fragments survive. Library, passages, Sources & Editions, local data/asset links and existing external URLs retain their existing routing. Web behavior is unchanged. Existing HTTPS-only opener permissions and user-click requirement remain unchanged.

Regression tests cover macOS `tauri://localhost`, Windows `http://tauri.localhost`, and the HTTP preview, including all four website pages, query/fragment preservation, trailing slashes and retained local routes. Fresh `npm run verify:both` passes: typecheck, production web build with 188 application / 50 Python-source checks, rebuilt offline frontend and all 19 desktop checks. Actual preview clicks from Library primary navigation, Library footer at 390px, and Sources using Enter open the public Downloads page in a separate browser tab while preserving the original local Library/Sources URL. Sources itself remains local. At 1280/390/320px the checked Library has no horizontal overflow; captured browser warnings/errors are empty. Evidence: `artifacts/review/desktop-website-navigation/verification.json` and `downloads-opened.jpg`. These preview checks exercise the browser fallback; a fresh signed-native opener check belongs to the new release. This source fix is local; published 4.3.1 installers and the frozen release have not been rewritten. A new signed desktop release is needed to deliver it to installed apps.

Larry authorizes preparing and releasing this correction as **4.3.2**. Preserve the published 4.3.1 artifacts; follow the signed release and own-terminal host-sudo workflow. See [4.3.2 release record](V4.3.2-Desktop-Release-2026-10-15.md).
