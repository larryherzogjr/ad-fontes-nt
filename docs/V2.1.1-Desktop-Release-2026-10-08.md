## Upgrade compatibility

The pinned Tauri macOS updater installs into the existing `.app` directory. Apple’s documented localized display-name mechanism makes an existing `Ad Fontes NT.app` appear as **Ad Fontes**, without moving it or invalidating Dock references. Base bundle-name metadata deliberately retains the legacy filename; English `InfoPlist.strings` supplies the visible name. Fresh packages use `Ad Fontes.app`; user-customized filesystem names remain respected. See Apple’s [CFBundleDisplayName rules](https://developer.apple.com/library/archive/documentation/General/Reference/InfoPlistKeyReference/Articles/CoreFoundationKeys.html). Prefer in-app updating for existing users; dragging a freshly named DMG app alongside the old filename can otherwise create two copies.

Windows uses a pinned Tauri 2.11.4 installer template with only the two registry identity keys fixed to their historic names. Existing install directories and main executable remain; DisplayName/PE product metadata/shortcuts use Ad Fontes. The postinstall hook renames only shortcuts targeting this installation and preserves unrelated/user-created shortcuts. An isolated CI upgrade test installs hash-verified public 2.1.0, upgrades/repeats 2.1.1, checks signature/name/single registration/shortcuts/data sentinel, uninstalls, and checks a fresh installation. This is automated runner coverage, not physical Windows 11 user acceptance.
